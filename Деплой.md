### 1. Требования

- VPS-сервер с Ubuntu 22.04 или новее;
- зарегистрированный домен или поддомен;
- доступ к серверу по SSH (SmarTTY, PuTTY);
- права на настройку DNS домена.

### 2. Настройка домена

У регистратора домена необходимо создать A-запись, которая будет указывать на IP-адрес сервера:
> Тип     Имя             Значение

> A         hackathon   123.123.123.123

### 3. Подключение к серверу по SSH

- ssh root@123.123.123.123;
- или использовать программу: PuTTY, SmartTTY или др.

### 4. После подключения к серверу выполнить:

```bash
sudo apt update
sudo apt install docker.io docker-compose-v2 -y
sudo systemctl enable docker
sudo systemctl start docker
docker --version
docker compose version
```

### 7. Запуск проекта

#### 1. Настройка HTTPS (SSL)
Перед первым запуском проекта в файле `nginx.conf` необходимо указать домен (16 строка: server_name hackathon.ваш-домен.ru;)

```bash
# создать директорию для проверки Let's Encrypt
mkdir -p certbot/www
```

```bash
# запустить проект
cd путь_к_проекту # перейти в папку проекта
sudo docker compose up --build -d # собрать и запустить контейнеры
sudo docker ps # проверка контейнеров
```

Проверить работу сайта по HTTP:

```text
- Главная: http://hackathon.ваш-домен.ru
- API: http://hackathon.ваш-домен.ru/api/health
- Административная панель: http://hackathon.ваш-домен.ru/admin  
```

Если сайт работает, можно получить SSL-сертификат. Выполнить (заменить домен и email на реальный):

```bash
docker run --rm -v /etc/letsencrypt:/etc/letsencrypt -v "$(pwd)/certbot/www:/var/www/certbot" certbot/certbot certonly --webroot --webroot-path=/var/www/certbot -d hackathon.ваш-домен.ru --email ВАШ_EMAIL --agree-tos --no-eff-email
```

После успешного выполнения команды сертификат будет сохранён на сервере в:

```text
/etc/letsencrypt/live/hackathon.ваш-домен.ru/
```

#### 2. Перезапуск Nginx

После успешного получения SSL-сертификата необходимо открыть файл `nginx.conf` и полностью заменить его содержимое на следующий код (необходимо указать домен (16 строка: server_name hackathon.ваш-домен.ru; )):

```nginx
worker_processes auto;

events {}

http {
    upstream backend {
        server backend:8000;
    }

    upstream frontend {
        server frontend:80;
    }

    server {
        listen 80;
        server_name hackathon.ваш-домен.ru;

        location /.well-known/acme-challenge/ {
            root /var/www/certbot;
        }

        location / {
            return 301 https://$host$request_uri;
        }
    }

    server {
        listen 443 ssl;
        server_name hackathon.ваш-домен.ru;

        ssl_certificate /etc/letsencrypt/live/hackathon.ваш-домен.ru/fullchain.pem;
        ssl_certificate_key /etc/letsencrypt/live/hackathon.ваш-домен.ru/privkey.pem;

        location /media/ {
            alias /media/;
            expires 30d;
            access_log off;
        }

        location /api {
            proxy_pass http://backend/;
            proxy_set_header Host $host;
            proxy_set_header X-Real-IP $remote_addr;
            proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
            proxy_set_header X-Forwarded-Proto $scheme;
        }

        location /api/ {
            proxy_pass http://backend/;
            proxy_set_header Host $host;
            proxy_set_header X-Real-IP $remote_addr;
            proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
            proxy_set_header X-Forwarded-Proto $scheme;
        }

        location / {
            proxy_pass http://frontend;
            proxy_http_version 1.1;
            proxy_set_header Host $host;
            proxy_set_header X-Real-IP $remote_addr;
            proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
            proxy_set_header X-Forwarded-Proto $scheme;

            proxy_intercept_errors on;
            error_page 404 = /index.html;
        }

        location = /index.html {
            proxy_pass http://frontend/index.html;
        }
    }
}
```

После этого перезапустить Nginx:

```bash
docker compose restart nginx
```

Проверить работу сайта (HTTP-запросы автоматически перенаправляются на HTTPS):

```text

- API: https://hackathon.ваш-домен.ru/api/health
- Административная панель: https://hackathon.ваш-домен.ru/admin  
```

```bash

sudo docker compose down # остановить контейнеры (перед пересборкой после внесения изменений в проект)

```

### 9. Важная информация

* домен или поддомен настраивается у регистратора домена и должен указывать на IP-адрес VPS;
* при смене сервера исходный код проекта изменять не требуется;
* при смене домена необходимо указать новый домен в `nginx.conf` перед первым запуском и при настройке HTTPS;
* менять адрес API при смене домена не требуется;
* база данных PostgreSQL создаётся автоматически при первом запуске проекта;
* параметры подключения к базе данных задаются в файле `.env`;
* SSL-сертификат выпускается Let's Encrypt;
* после настройки SSL сайт работает по HTTPS;
* сертификаты Let's Encrypt имеют ограниченный срок действия. Для долгосрочной работы необходимо настроить автоматическое продление сертификата;
* административная панель: https://ваш-домен/admin.

### 10. Создание пользователя административной панели

После первого запуска проекта база данных PostgreSQL создаётся автоматически, однако пользователь административной панели в ней отсутствует. Поэтому перед первым входом необходимо создать администратора.

Администратора можно создать двумя способами:

**Вариант 1 — через DBeaver**

Подключиться к PostgreSQL через DBeaver, используя параметры из файла `.env`, и добавить пользователя в таблицу администраторов.

При создании пользователя необходимо указать:

* логин;
* хеш пароля (сначала придумать пароль, потом захешировать его).

**Вариант 2 — через терминал сервера**

Подключиться к контейнеру PostgreSQL и выполнить SQL-запрос для добавления администратора:

```bash
sudo docker exec -it <имя_контейнера_базы> psql -U hackathon_user -d hackathon_db
```

После подключения выполнить запрос на создание пользователя.

> Важно: пароль администратора нельзя записывать в базу данных в открытом виде. В таблице должен храниться хеш пароля, сформированный тем же алгоритмом, который используется приложением при авторизации (bcrypt).

После создания администратора выполнить вход:

```text
https://ваш-домен/admin
```
